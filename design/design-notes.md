# 設計メモ — ちいかわ 郎 ラーメン

座標・寸法・判断の記録。実値は `build/lib/consts.py` を正とする（本書は意図の説明）。

## コンセプト

- 参考イメージ: 白い箱型の建物＋黄色い「郎」看板＋自動ドアの外観。
  赤いカウンター・背もたれ無しスツール・厨房・食券機の内観。
- 体験: 入店 → 食券 → カウンターに座る → **店員NPCをタップしてダイアログでコール** → ラーメン提供。**NGコールは退店**。

## 地形・基準

- フラット地形（bedrock/dirt/grass）。地表 `y = -60`。
- 立ち足元 `FEET_Y = -59`、店内床 `FLOOR_Y = -60`、天井 `CEIL_Y = -53`。
- スポーンは広場中央・店の手前 `(0, -59, -5)`、南（+Z＝入口）向き。

## 建物（外装）

- 店内範囲 X: -8..8 / Z: 0..16。白コンクリの壁、店先は水色ステンドグラス。
- 入口は中央 X: -1..0。**バニラの鉄ドア2枚（既定は閉）**。**中央の柱をなくして2枚の扉を
  隣り合わせに連結（両開き）**。足元（z=±1）の**感圧板**を踏むと開くバニラ挙動。
  Behavior Pack に依存しないので確実に動く。左右 x=-2,1 に灰色の枠（gray_concrete）。
- 「郎」看板は入口上の黄色地に黒のドット絵。漢字「郎」は Windows 同梱フォント
  （BIZ UDゴシック）から **13×13** に起こす（`_render_kanji_rows`）。店先の立て看板は**「郎」のみ**。

## 内装

- 赤いカウンター: Z=10、天板 `y=-58`。客席スツールは Z=8、X=-6,-3,0,3,6 の5脚。
- 厨房: Z=11..15。かまど／溶鉱炉／燻製器・大釜・樽・赤い暖簾。店員はカウンター奥のNPC。
- コールは**店員NPCをタップ**してダイアログで選ぶ（物理端末は廃止）。カウンター前の案内看板
  （`(0,-54,9)` の wall_sign）で「店員をタップしてニンニク入れますか？」と促す。
- **店内のNPC**（雰囲気づくり）: コール担当の店員のほか、店主(jiro_master, x=-4)・
  助手(jiro_helper, x=4)・常連客(jiro_guesta, x=-6,z=7)・学生客(jiro_guestb, x=6,z=7)を
  配置。タップすると役割別の**セリフ（ボタン無しのテキストシーン）**を話す。取引はしない。
  カウンター内の店員は yaw=180（客席側を向く）、席の客は yaw=0（カウンター側を向く）。
- **二郎風の店内掲示**: 左右壁に黄色い掲示帯を作り、食券/着席ルール、無料トッピング、
  ニンニク・ヤサイ・アブラ・カラメのコール表を看板で表示。食券機前には黄色/黒の
  行列マーカー、左奥にはセルフ水コーナー、カウンター上には卓上小物を置く。
- **歴史学習スポット**: 西壁入口寄りに歴史案内NPCだけを置く。年表ポスターやブック台は店内が
  ごちゃつくため撤去。歴史案内NPCは、年表/一杯の特徴/コール文化/広がり/マナー/ミニクイズを
  NPCダイアログ内のページ送り（前へ/次へ/目次へ）で説明する。ミニクイズは問題→選択肢→解答ページ。
- 食券機: 入口右手 `(6,-59..-54,3..4)` の**縦型**（幅3×高さ6×奥行き2）。実機で隣接した
  コマンドブロックの信号干渉が疑われたため、上=ミニ、中=小、下=大の**縦3段ボタン**を1段ずつ離し、
  ボタン前面と奥の隠しコマンドブロック（`/execute as @p[r=6] run function jiro/order_*`）で分離する。

## コール（ゲームの肝）

- 入力方式: **店員NPCのダイアログ**。`spawn_npcs` で NPC を召喚（位置タグ付け）し、
  `dialogue change @e[tag=jiro_clerk] jiro_call` でシーンを割り当てる。
  プレイヤーが NPC をタップするとそのダイアログがネイティブに開き、ボタンの
  `/scoreboard players set @initiator jiro_call N`（N=1..6）が発火する（`@initiator`
  がタップ本人に解決）。`loop` がそのフラグを拾って `call1..call6` を実行する。
- 選択肢（`consts.CALL_PRESETS`，6つ）は**正解と NG（罠）を交互**に並べて難易度を上げる:
  - ▉ 正解（OK=True）: `そのまま` / `ニンニク ヤサイ アブラ カラメ` / `全マシマシ` → `serve` で提供。
  - ╳ NG（OK=False）: `替え玉ください`（博多） / `大盛りで！`（二郎は「マシ」） /
    `はい`（返事だけでコールになっていない）→ 理由を表示して `fail` で退店。
- 正解コールは `call{{i}}` で具材スコア（`jiro_g/y/a/k/mm`）をセットしてから `serve`。
  `serve` は選んだ内容を `tellraw` で読み上げ、`give @s beetroot_soup 1` で**赤いスープの
  ラーメンを出す**。食べる判定や実食演出は使わず、受け取った時点で `jiro_state=5`（退店可）にする。
  - **運用方針**: 公式の NPC Dialogue は `dialogue change` / `dialogue open` の両方を持つ。
    このワールドでは、店員が店内に実体として立っている体験を優先し、`dialogue change` で
    事前にシーンを割り当てて**プレイヤーがNPCを直接タップ**する方式にしている。
    ボタンは `@initiator` でタップ本人に作用する。自由テキスト入力は Bedrock では不可。

## 進行（Behavior Pack）

- 床下の `repeating_command_block` → 毎 tick `jiro/main`。`tick.json` は `jiro/noop` にして二重実行を避ける。
  `jiro_state` でプレイヤー毎に管理。
  スコアボードは `jiro_state / jiro_sec / jiro_call / jiro_sys` ＋具材
  `jiro_g / jiro_y / jiro_a / jiro_k / jiro_mm`。
- 実機で `tick.json` が走らない/遅れる場合に備え、食券機の `order` は最初に `boot` を呼ぶ。
  `boot` はスコアボード作成＋NPC召喚（`spawn_npcs`）を行う。さらに NPC ダイアログの各ボタンは
  `jiro_call` を立てるだけでなく `execute as @initiator run function jiro/callN` を直接実行する。
  これにより、tick の `loop` に依存せず食券→NPC→提供まで進む。
- 状態: 0 店外 / 1 食券購入 / 3 コール中(店員をタップ) / 5 提供済(退店可)。
- NPC（店員＋雰囲気）が居なければ `spawn_npcs` で召喚しダイアログを割り当て。カウンター
  着座検知で `ask`（state=3 にして具材スコアを初期化、案内表示）。
- コールは NPC ダイアログのボタンが `jiro_call` を立て、`loop` が `call1..call6` を実行。
  正解は `serve` で提供済み。NG は `fail` で退店。
  退店（広場）で `reset_player` し再挑戦可能。
- NPC スキンは公式ドキュメント上もNPC編集画面の Appearance で選ぶ機能。`/summon npc` や dialogue JSON で
  安定してスキン番号を固定する公式方法は見つからないため、生成後に creative/operator でNPCを右クリックし、
  Appearanceから店員/客の見た目を選ぶ運用にする。

## 画像と店内装飾

- ちいかわ画像は `tryashtar/image-map` のCLIで Bedrock の地図データへ変換し、2×2の
  額縁画像として配置する。左壁 `ちいかわとはちわれ` は map `1000`-`1003`、右壁
  `ちいかわとはちわれ_2` は map `1100`-`1103`、キッチン壁 `シーサーと鎧さん` は
  map `2000`-`2003`、店外パネル `ちいかわラーメン` は map `3000`-`3003`。
- カスタムブロック壁画は MEE で BP 全体を読み込ませない原因になったため使わない。
- 代わりに、店内は**ラーメン二郎に寄せた掲示・導線**へ変更。黄色いメニュー札、無料トッピング表、
  食券/着席ルール、行列マーカー、セルフ水コーナーを vanilla blocks/signs で表現する。
- 左右壁中央の Image Map 額縁エリア（おおよそ z=5..7 / y=-56..-57）の前後には壁掛け看板を置かない。
  食券/水/コール表の看板は z=2,9,13 へ分散し、画像の前に看板が浮いて見えないようにする。
- `tools/ImageMap4-Windows/ImageMap-cmd.exe` を `new_world.py` の後段で呼び出し、LevelDB の `map_*`
  データを追加する。額縁ブロックは `geom.set_filled_map_frame` で `frame` + `ItemFrame` BlockEntity を
  直接配置する。リソースパックや実験的機能は不要。

## 保護・運用

- 広場外周にバリア、地中に deny。既定はアドベンチャー（展示が壊れない）。
- 編集時は `/gamemode creative`。コマンド・教育機能は有効。

## 実装上の注意（ハマりどころ）

- Python は **3.12 固定**（`py -3.12`）。3.13 は Amulet 非対応。
- Bedrock の樫の壁掛け看板ブロック名は **`wall_sign`**（`oak_wall_sign` は Java 名で
  変換できず Block Entity が落ちる）。立て看板は `standing_sign`。
- `quartz_slab` は余計な状態を付けない（`minecraft:vertical_half` は無効）。
- 生成作業は OneDrive 外（`%TEMP%`）で行い、`.mcworld` だけ `dist/` へ。
- `level.dat` は本体生成（Amulet save）の**後**に作り込む（save が上書きするため）。
- Bedrock の会話 UI は `minecraft:npc_dialogue`。NPC への割り当ては `/dialogue change`。
  **ボタンのコマンドは「プレイヤーが NPC を直接タップして開いた」ときだけ発火**し、
  `/dialogue open` コマンドで開くと発火しない。よって自動オープンせず、`dialogue change`
  だけしてタップに任せると `@initiator` がタップ本人に解決してボタンが動く。
  1シーン最大 6 ボタン、押すと閉じる。自由テキスト入力は不可（ボタン選択のみ）。
- **Behavior Pack の `min_engine_version` は `[1, 20, 0]`**。高すぎる版（例 `[1,20,80]`）に
  すると古いエンジンでパックが黙って無効化され、NPC・食券・コールが全部動かなくなる。
- **BP の UUID/version は大きな仕様変更時に更新する**。MEE は同じ UUID/version の旧BPを
  キャッシュして使うことがあり、壊れた旧パックを参照し続けると店員NPCも食券機も動かない。
  今回は BP UUID を `...ffeeb0`、version を `[1,9,0]` に更新し、`world_behavior_pack_history.json`
  も同梱してインポート時に新パックとして認識させる。
- **最重要の教訓：カスタムデータドリブンブロックは MEE で BP 全体を壊す**。以前は壁画を
  カスタムブロック（`jiro:mw_*/me_*` 132個）＋リソースパックで作り、`experiments.
  data_driven_items=1`（Holiday Creator Features）を付けていた。しかし Minecraft Education は
  この実験的機能を安定してサポートせず、ワールドを取り込むと**BP 全体が拒否**され、
  店員NPC・食券機（`/function jiro/order` が存在しない）・画像が**全部同時に動かなくなった**。
  → 解決策はカスタムブロック/RP/実験機能を**完全に撤去**し、画像壁画をいったん停止すること。
  `mural.py` / `panels.py` は参考として残してあるが未使用。`world_resource_packs.json` は空 `[]`。
